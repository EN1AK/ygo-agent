# 交互诊断样本试点：目标离场不等于错误，付出资源也不等于浪费

## 结果与当前门槛

从既有 SkyStriker 新旧 WindBot 配对评测中整理 **500 个候选连锁窗口**，覆盖 128 个有效对局、32 个种子簇。旧/新模型和两个座位的同种子对局始终作为一个相关组，不冒称 128 个独立随机样本。没有重跑 128 局；仅额外 CPU 重放一个现有窗口所在对局，保留所有原始证据。

这是候选证据库，不是 500 条已证明的策略优劣标签，也不是已经可拟合的完整监督集。

| 可观察事实 | 窗口数 | 边界 |
|---|---:|---|
| 已选场上目标在首个结算开始前离场 | 49 | 23 个涉及对方目标，26 个涉及己方目标 |
| 同链出现 disabled/negated 消息 | 260 | 旧文字日志未打印 link，不归因到最后发动者 |
| 已公开的弃牌与同链禁用/无效消息并存 | 112 | 共现，不是每次都已核实因果 |
| 已公开的弃牌后出现场上卡被破坏 | 3 | 包括破坏自己的卡，不能当作有收益 |
| 逐效果成功、成本 reason、无法逃离、策略价值 | 全部 unknown | 不用缺少事件冒充负例 |

采样按对局轮流取窗口，并优先检查离场/弃牌/多连锁，是**结果富集的诊断样本**。不能用其频率或未来 Brier 分数声称真实对局总体校准水平。

## 人工逐行抽查

以下行号属于原始 `training-runs/sky186-121-windbot-fresh-20261004/` 各局的 `eval.log`，每份文件哈希在样本 manifest 中。

1. `old121m/attempt-0004`，424–487：模型抓锚取对方零衣；零衣连锁解放，随后燎里登场。目标离场为事实，是否存在更优长期策略尚未验证。
2. `old121m/attempt-0009`，5134–5206：WindBot 多任务战刀机取**己方**零衣，然后自己连锁零衣解放。不能归入“对手躲掉我的打断”，也不能只因目标离场就惩罚。v2 明确保存发动者/目标控制者/己方或对方关系。
3. `old121m/attempt-0003`，334–360：交闪→灰流丽，灰流丽弃牌后出现 disabled 消息。此处只标同链共现，不能凭旧日志给 disabled 指定来源。
4. `new186m/attempt-0006`，3041–3094：模型双龙卷弃掉另一张双龙卷，选择破坏自己的多任务战刀机。说明“支付成本后出现破坏”绝不能直接成为正向偏好标签。是否值得如此操作仍是待验证战略问题。
5. `new186m/attempt-0032`，3293–3340：模型燎里发动回收，WindBot 遮蒙取燎里，之后出现 disabled。为解决来源不明，额外捕获下面的原始报文。

这些是指定样例的人工抽查，不是 500 个窗口全部已逐局人工验收；不能报告整体标注准确率。

## 新的明确正向效果对照：遮蒙确实禁用了燎里效果

home CPU 重放 seed 2026104415 / player 1，原始 argmax、无动作覆盖、无 Q/search/cycle guard、两个低优先级逻辑 CPU。82 个决策的菜单、选中动作、模型身份与原始 GPU 对局逐项相同；不要求 logits/V 逐位相同，不声称完整隐藏引擎状态克隆。

原始公开链报文：

- packet153：link1，燎里 `63288573`，actor1。
- packet155：link2，遮蒙 `97268402`，actor0。
- packet157/158：link2 开始/完成结算。
- packet159：开始结算 link1。
- **packet160 `014c01`：CHAIN_DISABLED 明确指向 link1，而不是遮蒙的 link2。**

因此这次燎里的当前效果确实被禁用，不只是“结算了”。结合之前遮蒙取零衣、零衣连锁解放的案例，可以形成“相同卡在不同响应条件下产生不同后果”的开发对照。新的遮蒙由 **WindBot** 操作，模型是燎里控制者；不宣称模型已学会正确使用遮蒙。也没有证明燎里在所有可能分支都无法逃离，或证明这是最优动作。

新捕获目录 `training-runs/interaction-kagari-counterexample-20261004/`，含完整 yrp、engine.log、decisions.jsonl、5 份有限数组观测夹具与报文。验证文件 `counterexample-verification.json`：82 菜单/动作一致、5 NPZ 哈希/有限性通过、native 与 actor 前后不变。对局最终第11回合自然失败；这不是新强度评测。

## 划分、数据缺口与下一步

v2 的 `windows.jsonl` SHA256 为 `32dbfd21ec5079f0e9c552251facb24bb900fec32e6e35eb0e20aa78039ac975`；已在拟合前保存候选划分：train156、validation17、test31、开发根16、交叉冲突隔离280。

规则：seed 和交互卡片组合各自 SHA256 分桶，只有二者分区相同才入组；旧已研究 seed2026104421 只作开发。三个拟合分区之间无 seed 或组合交集。同一完整对局的窗口不会进入不同拟合分区。大量隔离是防泄漏代价，不能为了凑数移回训练。

**task2.3 尚未完成**：现有 JSONL 只有菜单/logits/V，没有全部窗口动作前的完整 actor 观测和循环状态。新补抓的 5 份夹具属于一个对局，不能复制成独立训练/测试样本。完整日志还可能包含私有信息，当前工具绝不直接导出为学生输入。

按 OpenSpec 的数据门槛，暂不拟合四个探针、不计算虚假的 held-out F1/Brier。后续需要为所选独立窗口补抓动作前观测及原始带 link 的消息，进一步核验成本与效果状态，完成输入字段白名单审计后才能拟合。当前仅 task2.2 的有界采集/覆盖率/抽查完成；覆盖不足明确阻止泛化结论，预测能力仍未验证。

原生 selection 差异仍是生产迁移的独立未解决项。活动 PPO 不改配置、不替换 native、不接入这些标签。源代码按 local/GitHub/home 同步，H200 依用户要求离线待同步。
