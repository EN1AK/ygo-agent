# 首轮题库教学：局部学会，前缀退步，未推广

2026-10-08。用户批准先做一个有界可学习性实验，不等待 24 道题全部建成。本轮已完成正常起手采集、独立审计、32 次示范更新、三组短 PPO 对照及冻结复测。结论是：**可以教会鳞茎攻击表示复活并用枪管龙二连击，但只教后缀会损坏前面的玻纤发动选择。正式模型保持原版本。**

## 实际结果

每项含三个同家族开发变体，每个变体重复两次且轨迹完全一致；下表分母为变体数，不把重复运行算成新题。仅 variant 0 的两个成功后缀进入教学。

| 模型 | 鳞茎表示窗口：二连击清场 | 玻纤窗口：二连击清场 | 从玻纤接手时枪管龙攻击次数 | 疾风直接攻击 |
| --- | --- | --- | --- | --- |
| 原 100M 父模型 | 0/3 | 0/3 | 各 1 次 | 3/3 |
| 32 次示范教学 | **3/3** | 0/3 | **各 0 次** | 3/3 |
| 原模型 + PPO 16384 步 | 0/3 | 0/3 | 各 1 次 | 3/3 |
| 教学模型 + PPO 16384 步 | **3/3** | 0/3 | **各 0 次** | 3/3 |
| 原模型 + PPO 18432 步 | 0/3 | 0/3 | 各 1 次 | 3/3 |

旧四个合成根在五个模型上二值结果相同：疾风直接攻击成功；combo、被无效后的战斗和燎里交互失败。不能因为这个粗粒度回归分数未变，就说没有能力退步。

具体新错误位于 `teach-03/after/combo-v0-combo-0.json` 第 24 步（零起算）：模型取消玻纤效果，随后进入战阶，速攻同调士和玻纤攻击青眼，没有做出枪管龙。教学后 PPO 的同根仍出现这一错误。原模型则能展开到枪管龙，但鳞茎选择守备表示复活，后续只能攻击一次。

这个现象支持“目标后缀可学习、短 PPO 后仍保留”的有限结论；不支持完整 combo、跨家族迁移、胜率或等算力优势。`learnability_gate_passed=true` 仅指清单中的后缀与疾风局部门槛，**不是完整能力或生产推广门槛**。

## 题目和历史如何构造

使用冻结 MR4 核心、未启用禁限卡表。双方主卡组各 40 张、同名卡最多三张，正常初始手牌/抽牌与先攻限制；初始化只把卡放入主卡组/额外卡组，没有 Debug 布场、任意 LP 或首回合战斗开关。它验证这个冻结规则环境中的可达性，不声称现行赛事合法。

combo：对手先用两张古之规则放出两只守备青眼。己方以电子龙、速攻同调士及通常召唤遮蒙者进入玻纤，拉鳞茎；玻纤、鳞茎和速攻同调士做枪管龙。正确后缀让鳞茎攻击表示复活，再转守备获得二连击，清掉两只青眼。起始 LP 均为 8000，目标是局部清场，不是斩杀或已证明的全局最优。

疾风：对手古之规则放出攻击表示青眼；己方正常召唤零衣、Link 疾风。正确分支直接攻击造成 1500 伤害且自身无伤；对照撞青眼自身损失 1500。固定对手策略和牌序明确属于条件设定。

`opening-02` 与 `battle-01` 各三变体、两个分支、两次重放，共 24 次采集。独立 C API 对每对记录取一条验证，共 12 条、330 个原 actor 决策、903 个原始响应；另外检查逐行张量哈希、全部事件、终局面和目标判定。两个重复全算的最终参考采集为 1806 个响应。三个变体只更换无关填充怪兽，均为 development；它们和旧合成题、不同接手切片不跨训练/测试家族。

原 actor 张量、合法菜单、强制动作历史沿用既有实现。每次更新用当前参数从该座位完整正常对局前缀重算 RNN；另一座位记忆在在线评测中独立推进。批量训练保留本座位全部观测，padding 和教学根之前不计监督损失，完整前缀参与梯度传播。顺序推理与 time-major 批量序列最大 logits 差为 `5.7220458984375e-06`。

## 教学配置与对照边界

预声明清单：`assets/exercises/teaching-v1/plan.json`。原 checkpoint 副本开始，Adam 学习率 1e-4、梯度裁剪 1、32 次更新；两条长度最多 32 的序列，combo 后缀与疾风后缀各占一半损失权重。只示范一个合法解，不把其余未探索动作标为错误；原环境奖励不改，未引入 Q-boost、搜索或辅助预测头。诊断模式默认关闭优化器，必须显式 `--execute` 才教学。

三组 PPO 使用同一生产 native、SkyStriker 固定牌组自博弈、seed 8102026、16 环境/4 线程、64 步采集、2 minibatch、1 epoch、学习率 1e-5、关闭 UPGO 和并发训练。详细参数和每组命令在证据目录。

额外普通 PPO 的 2048 个训练输入等于 `32 × 32 × 2` 个含 padding 的教学输入，**只匹配 learner 输入数量**。两种损失、有效监督数量、梯度计算和采集成本不同，不是严格等 FLOPs 或等墙钟对照。未测未见家族、双座位、多对手完整对局，因此 OpenSpec 6.1–6.3 保持部分完成。

教师没有运行搜索。参考构造/初步试错、native 编译、前两次未完成尝试以及全部审计/评测的合计墙钟未统一计时，不能从上表推导端到端加速比或总计算优势。32 次优化与每臂 900 秒运行上限均未追加。

## 可复核性与失败记录

- 第一次教学因默认 GPU 矩阵乘精度下顺序/批量 logits 差约 0.009，门槛拒绝，未启动优化器。改为全 float32 乘法后通过。
- 第二次在第一步编译/更新期间 H200 被暂停，未写出任何已完成更新指标。恢复后核对旧进程已消失，从原父模型另建 `teach-03` 执行 32 次，没有接着累加旧更新。
- 普通单牌组的 `cleanba --config-only` 原本只在 deck sampling manifest 分支内生效。已将退出移至通用路径；三组实际配置检查正常返回，未启动训练。早先设置不受当前 JAX 支持的环境变量值时在导入阶段停止，同样未训练。
- 教学后及三个 PPO 模型的 36 条正常起手代表轨迹全部通过独立 C API 重放、事件/状态和张量关联检查；16 条旧合成代表轨迹也通过独立核心重放。每条均另有第二次一致运行。PPO 模型均通过正常 checkpoint 兼容性加载。
- 两套隔离运行时清单（各 14093 件文件）在实验结束再次逐项核对；生产 native 和父模型未改。源码使用干净 Git archive，没有把本地用户 BO3 header 改动带入桥接构建。
- 本地针对性测试 `test_exercise_teaching`、`test_exercise_actor`、`test_capability_exercises` 共 16 项通过；新增评测/审计入口语法检查通过，OpenSpec strict validation 通过。
