# Qwen 直接 RL 的前缀 KV 复用（2026-10-13）

本实验在 `experiment/jev-direct-rl` 分支实现真实 token 前缀缓存，仍直接后训练
Qwen3-4B 内部 LoRA，不新增 PPO 策略。服务器原 JAX 训练与控制器保持停止。
设备为单张 H200；性能结果不代表策略强度或收敛速度提高。

## 实现与正确性

- 原输入前部频繁变化的场面限制了缓存。旧记录中，相邻同局同座位请求的最长公共
  token 前缀中位数为 1718，公共前缀总量约为输入总量的 27.93%。
- 新增 `cards-first-v1` 布局：只将当前已有的可见卡文前置，原场面、事件、分支结果、
  合法选项继续完整输入，无截断。没有把假设分支里见到的卡积累到真实主局。
- `recompute` 和 `reuse` 使用完全相同的输入、前缀边界、注意力内核和两段计算。
  前者每次重算前缀，后者按实际 token 元组复用；单次完整计算另设固定输入对照。
- 缓存后缀采用右对齐因果注意力，保留绝对位置。每次创建独立缓存容器，分支不修改
  共享前缀。参数版本变化后旧缓存失效；训练中途改参数则立即报错。
- 训练不会简单丢弃前缀梯度。每次后缀反传得到的 KV 梯度用 FP32 累加，缓存淘汰或
  组末时重建一次前缀图，将这些梯度一起传回原 LoRA。参数在整个组内固定。
  数学上为 `(各决策对 KV 的梯度之和) × (KV 对参数的导数)`。
- BF16 中求和顺序改变会产生数值差异。小型真实 Qwen 的 FP32 完整参数梯度测试检查
  等价性；4B 实测单独记录差异，不声称更新逐位相同。采样/训练概率门槛仍为 `1e-4`。

实现主体为 `ygoai/rl/jev_prefix_kv.py`，接入 `jev_qwen_policy.py` 与 `jev_parallel.py`。
完整对局对照源码为 `19eff631f80eb78c5a9a9251f35e9b4de1e711c6`；后续固定输入
三路对照源码为 `7c46dbe87e95253d7a8837e651a84010f2c151f5`，缓存和训练核心相同。
Qwen revision、基座分片、原生模拟器和牌组资产沿用前次固定配置，各运行记录实际哈希。

## 固定真实输入测试

从先前完整对局取连续 48 个决策，包含 50 条层级选项提示。预热后同步计时。
两路初测缓存命中 42/50 次，跳过 85,945 个前缀 token，重算 15,971 个前缀 token；
后缀为 187,535 token。采样动作概率最大差为 0。

初测重算/缓存的前向耗时为 9.254/6.738 秒，完整前向反向为 24.286/18.237 秒，
峰值显存为 90.71/53.00 GiB。梯度 FP64 归约核验：方向余弦 0.999922671，
相对 L2 差 1.25036%，最大绝对差 0.00650883。初版 FP32 长向量余弦归约误差产生了
略大于 1 的结果，已保留原证据并用 FP64 修正，后续脚本统一使用 FP64 度量。

补充三路对照（同一批 token，`compute-002`）：

| 计算方式 | 前向秒 | 前向＋反向秒 | 峰值显存 GiB |
| --- | ---: | ---: | ---: |
| 单次完整计算 | 8.479 | 22.453 | 90.46 |
| 前缀＋后缀，每次重算 | 9.278 | 24.043 | 90.49 |
| 前缀 KV 复用 | 6.762 | 18.312 | 52.78 |

缓存相对单次完整计算仍节省 **20.3% 前向时间、18.4% 前向反向时间**，因此收益并非
仅来自拆分基线较慢。拆分后 BF16 概率相对单次完整计算的最大差为 0.0449645，
不能宣称两种计算形状在低精度下逐位等价；缓存开关的两段对照概率差为 0。
本次缓存/重算梯度方向余弦 0.999934234，相对 L2 差 1.14694%。

## 配对完整对局与一次实际更新

两种模式各 2 局，2 个 actor，微批量 1，关闭梯度检查点，固定同开局和逐局采样 RNG，
零 baseline、学习率 1e-6。双方由同一组冻结模型驱动，组末更新学习方 LoRA。
每局仍最多 2 次、深度 4 的模型自主 oracle 推演。与旧输入布局的运行不直接比较时长。

| 阶段 | 每次重算秒 | KV 复用秒 | 省时 |
| --- | ---: | ---: | ---: |
| 对局采集 | 268.120 | 196.405 | 26.7% |
| 独立重放验证 | 7.855 | 7.656 | — |
| 实际训练更新 | 377.523 | 293.657 | 22.2% |
| 总计 | **653.609** | **497.826** | **23.8%** |
| 峰值显存 GiB | **124.03** | **89.32** | 降低 28.0% |

总耗时从模型加载完成起计，包含采集、重放、更新及保存。吞吐提高 **1.313 倍**。
两组都是自然终局，独立重放通过，保存适配器与优化器，进程退出码为 0。
851 次模型选择（含假设分支）、861 条提示、7,625,337 输入 token、464 个学习方操作。
主局及全部分支的输入、选项概率、动作和原生审计逐项一致。主 JSONL 另有每局一条
终局奖励汇总；排除这些非决策行、合并分支记录后，按 `sample_id` 核验共 851 次选择。

推理命中 **792/861（92.0%）**，跳过 2,255,380 个前缀 token，约占原总输入 29.6%；
训练命中 424/468，将 1,350,352 个重复前缀 token 缩至 117,589 个首次计算 token，
并用 44 次前缀反传完成累积梯度。缓存峰值驻留约 27K 个前缀 token。
采样/训练 log probability 最大差均为 **0**，损失相同，实际跟踪参数变化约 1e-6。

更新后的两组适配器因 BF16 归约不同而不逐位相同：2,949,120 个参数中，最大差
1.99972e-6，RMS 差 7.27240e-8，4,149 个参数差超过 1e-6；不能推断多轮强度等价。

## 使用与边界

在并行入口添加：

```sh
--prefix-mode reuse --no-checkpoint --batch-size 1
```

默认模式仍为 `off`；`recompute` 是相同新布局的无缓存对照。缓存默认最多 8 项、
合计 32768 个前缀 token，超大前缀直接重算。当前仅支持不补齐的单条提示、零 dropout、
全注意力，未实现多卡共享 KV。恢复本次适配器时须继续使用卡文前置布局；后续保存的
适配器说明增加 `input_layout` 字段，实际运行配置亦记录模式。

当前不是无限增长的整局聊天缓存。前缀之后的场面、事件和选项会变化，仍需计算；
后缀还须关注前缀 KV。更长输入、更大卡文集与不同牌组仍须重新测显存和吞吐。
oracle 推演使用真实隐藏状态这一既有实验限制未改变，不能视为公平信息集对战评估。
